Open Directional Sensitivity Calibration

Measures primary-submovement overshoot/undershoot across 8 counter-clockwise directions (odd-sensor-ccw) using raw Pointer Lock input.

Turn the directional curve off first. The browser sees motion after the mouse or host filter has applied it, so a calibration through an active curve is relative to it and recalibrating undoes the last one. Glorious Series One Pro with the patch: Turn curve off for calibration below, or python3 tools/odd_profile.py reset (Linux, RAM only); other firmware with the HID protocol: SET_ENABLED mode 2 (bypassForCalibration() in integrations/openmouse); Linux: stop odd_evdev_filter; QMK and devicetree curves: flash a flat curve.

Send to mouse (WebHID: Chrome or Edge on Windows, macOS and Linux): a Glorious Series One Pro with the open-directional-dpi patch, by cable or through its 2.4 GHz receiver, or a device with [OpenDDPIv1] in its product name. Until it sees the patch's DP01 stamp, the page sends only the stock version query. A sent profile lasts until the mouse powers off; Save on mouse keeps it (each save erases a flash page, so save once at the end). If Connect does not work with the page opened as a file, serve it from localhost (python3 -m http.server in this folder). On Linux, Chrome needs write access to the mouse's /dev/hidraw node. Not yet tried on a real mouse (2026-11-13).

Motion: the browser's event rate shows after the first flick. Browsers can merge mouse reports, so this page does not see each report; movement sums stay exact. Per-report timing needs a raw log (mouse-log provider, calibration/README.md).
